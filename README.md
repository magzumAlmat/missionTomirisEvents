# EventTomiris — городской квест на QR-кодах

Стек:

- **React (Vite)** — отображение контента квеста (точки, загадки, прогресс, финал).
- **Node.js + `qrcode`** — генерация QR-кодов для точек.
- **Node.js + Express** — бэкенд для Telegram-уведомлений (кнопка «Я прибыл»).

QR-коды **статические**: внутри зашит адрес вида `<сайт>/#/s/3`. Пока сайт размещён по этому адресу — коды работают вечно, срока годности нет.

## Быстрый старт

```bash
npm install
cp .env.example .env      # затем впиши токен и chat_id (см. ниже)
npm run dev               # сайт: http://localhost:5173
npm run server            # бэкенд Telegram: http://localhost:3001
```

Для «Я прибыл» нужны оба процесса (`dev` и `server`) — запусти в двух терминалах.

---

## 1. Редактирование квеста

Всё содержимое — в **`src/questConfig.js`**. Для каждой точки: `id`, `name`, `task` (загадка), `answers` (список верных ответов — регистр/пробелы/«ё» не важны), `letter` (буква за верный ответ), `nextHint` (куда идти).

Правило: буквы всех точек по порядку должны складываться в `finalCode`. Сейчас `П-Р-И-З-2-0-2-6` = `ПРИЗ2026`. Меняешь количество точек — приведи буквы к `finalCode`. Этот же файл читает генератор QR, так что список точек всегда синхронизирован.

---

## 2. Генерация QR-кодов

Сначала размести сайт (шаг 4) и узнай его адрес. Затем:

```bash
npm run qr -- https://твой-логин.github.io/EventTomiris/
```

В папке `qr-output/` появятся PNG на каждую точку (`point-01.png` …), стартовый `start.png` и печатный лист **`qr-output/index.html`** — открой его и нажми Ctrl/Cmd+P, чтобы распечатать все коды с подписями.

## 3. Telegram: кнопка «Я прибыл»

Как это работает: участник жмёт «Я прибыл» на точке → фронт шлёт запрос на бэкенд (`server/index.js`) → бэкенд отправляет сообщение в Telegram. Токен живёт только на сервере (в `.env`) и не виден посетителям сайта.

Настройка:

1. **Токен.** В `.env` → `TELEGRAM_BOT_TOKEN`. ⚠️ Токен, что ты присылал в чате, перевыпусти в **@BotFather** командой `/revoke` и вставь новый — старый скомпрометирован.
2. **Куда слать.** Напиши своему боту в Telegram любое сообщение (или добавь его в группу организаторов и напиши там). Запусти `npm run server` и открой <http://localhost:3001/api/chat-id-helper> — увидишь `chat.id`. Впиши его в `.env` → `TELEGRAM_CHAT_ID`.
3. Перезапусти сервер. Готово — кнопка «Я прибыл» будет присылать в этот чат: имя команды, номер и название точки, время.

На старте квеста участник вводит название команды/имя — оно попадает в уведомление. Поле показывается только если бэкенд подключён (`VITE_API_URL` задан).

> Локально `VITE_API_URL=http://localhost:3001`. Когда выложишь бэкенд в интернет (см. ниже), поставь сюда его публичный адрес и пересобери фронт.

## 4. Размещение (бесплатно)

**Фронтенд (статика)** — GitHub Pages / Netlify / Vercel:

```bash
npm run build      # результат в dist/
```

Выложи содержимое `dist/`. На GitHub Pages удобно через ветку или Actions; `base: "./"` в `vite.config.js` уже настроен на работу из подпапки. Благодаря HashRouter отдельная серверная настройка маршрутов не нужна.

**Бэкенд (Telegram)** — нужен хостинг, умеющий крутить Node.js: Render, Railway, Fly.io, VPS. Задай там переменные окружения из `.env`, запусти `npm run server`, а его публичный адрес пропиши во фронтовый `VITE_API_URL` и пересобери фронт.

Если кнопка «Я прибыл» не нужна — бэкенд можно не поднимать: оставь `VITE_API_URL` пустым, и кнопка просто не появится.

## Маршруты сайта

| URL | Экран |
|-----|-------|
| `/#/` | старт, ввод команды, прогресс |
| `/#/s/:id` | точка: загадка, «Я прибыл», проверка ответа |
| `/#/progress` | собранные буквы, список точек |
| `/#/final` | ввод финального кода |

Прогресс хранится в браузере участника (localStorage) — не теряется между сканированиями.

---

## Безопасность и честность

Ответы проверяются в браузере — для дружеского квеста нормально, но технически подкованный участник может подсмотреть их в коде. Если важна строгость — не делай ответы очевидными, а финальный приз держи офлайн. Файл `.env` с токеном никогда не коммить (он уже в `.gitignore`).
